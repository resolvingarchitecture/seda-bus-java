## Design quality · 43%

**Progress: 3 of 44 tasks done (7%)** ▰▱▱▱▱▱▱▱▱▱

- [ ] 🔴 **The public surface is explicit and the rest is internal.** SEDAMessageChannel became public through getChannel. No exported-API list and no module-info. **Fix:** List the supported public API and add module-info exporting only ra.sedabus.
- [ ] 🔴 **The public contract is documented.** The Javadoc does not state per-operation nullability, errors or thread-safety, for example for publish, completed or registerChannel. **Fix:** Document inputs, return meaning, errors and thread-safety for each public method.
- [ ] 🔴 **A versioning and compatibility policy exists.** No versioning or deprecation policy. The behaviour change sits under Unreleased while the pom is 1.3.1. **Fix:** State semver rules, what counts as breaking, and a deprecation window.
- [ ] 🔴 **Lifecycle is defined, including what happens to work in flight.** restart() makes a new pool without re-registering concurrency permits (they default to 1). Channels stay paused after shutdown. The pool force-stops after 5s. **Fix:** On restart, re-register permits and unpause channels. State the fate of in-flight work.
- [ ] 🔴 **Thread-safety is stated for every shared component.** DESIGN.md has general concurrency notes. getSubscriptionChannels returns an unsynchronized list. Per-component guarantees are not stated. **Fix:** State the thread-safety of each public class and method.
- [ ] 🔴 **Every queue, buffer, cache and map is bounded, with a stated policy at the limit.** deadLetter.json grows without bound (TODO.md). Block uses queue.put with no timeout, although the enum doc says up to the send timeout. **Fix:** Rotate or cap deadLetter.json and add a Block timeout.
- [ ] 🔴 **Failure modes are listed for each operation.** DESIGN covers retry and shutdown, but not per-operation failure modes for publish, registerChannel or resumeUnprocessed. **Fix:** Add a failure-mode table per public operation.
- [ ] 🔴 **No failure is silent.** giveUp ignores deadLetter()'s false return on an IOException, so the envelope is acked and its persisted copy deleted. **Fix:** Keep the persisted copy and notify the listener when the dead-letter write fails.
- [ ] 🔴 **Retry is bounded, backed off, and safe.** Retries are bounded with jittered backoff. A failed pubSub fanOut retries the whole fan-out, re-publishing to subscribers that already accepted. **Fix:** Track per-subscriber hand-over and retry only the subscribers that failed.
- [ ] 🔴 **Delivery guarantees match the implementation.** persist() returns true when channelDir is null, so an AtLeastOnce or ExactlyOnce envelope on an AtMostOnce channel is never persisted. **Fix:** Reject or persist guaranteed envelopes on in-memory channels, and document which.
- [ ] 🔴 **Failure paths and concurrency are tested, and time and I/O can be faked.** Tests use sleeps. There is no injectable clock or file system and no crash-mid-write tests (TODO.md). **Fix:** Inject a clock and store, and add crash and fault-injection tests.
- [ ] 🔴 **Documentation matches the code.** TODO.md says retry is immediate and the test flaky. Code has backoff and the test fixed. DESIGN routing pseudocode omits peek and restore. **Fix:** Update TODO.md, DESIGN.md and the risk register to match the code.
- [ ] 🔴 **The project can continue if its owner is unavailable.** The build is public, but the release process and jitpack access are undocumented. **Fix:** Write a release runbook in the repository.
- [ ] 🔴 **Contracts are machine-readable and tested.** CORRECTNESS_SUITE.md is prose. Each port hand-maps tests to it, with no shared test vectors. **Fix:** Publish machine-readable test vectors that every port executes.
- [ ] 🔴 **Change follows compatibility rules.** No compatibility or deprecation rules for the MessageBus API used by service-bus and 1M5. **Fix:** State additive-only changes and a deprecation window.
- [ ] 🔴 **Delivery semantics and ordering are stated for each channel.** Delivery levels are stated per channel. Ordering is not. **Fix:** Add ordering guarantees to the delivery semantics table.
- [ ] 🔴 **Complexity does not exceed team capacity.** Seven ports kept in lockstep by one person, with no capacity statement. **Fix:** State capacity limits or prioritise which ports are maintained actively.
- [ ] 🟡 **Persistence sits behind a boundary.** persist, removePersisted, deadLetter and delivered.log file I/O all sit inline in SEDAMessageChannel, with no store class. **Fix:** Extract a ChannelStore class for envelope, dead-letter and delivered-id files.
- [ ] 🟡 **Components are cohesive and of reasonable size.** SEDAMessageChannel (~600 lines) handles queueing, delivery, retry, dead-letter, persistence and dedup. **Fix:** Split out persistence/dedup and retry into their own classes.
- [ ] 🟡 **Failures are reported in one consistent way.** Failures surface as boolean returns, error messages on the envelope, callbacks, a listener and logs, applied unevenly. **Fix:** Define one failure channel per operation type and document it.
- [ ] 🟡 **Ordering guarantees are stated, and so is where they stop.** Ordering is not stated. Retries re-queue at the tail and concurrency above 1 reorders. **Fix:** Document per-channel FIFO only at concurrency 1 without retries.
- [ ] 🟡 **Durable writes follow a stated protocol.** Writes use a temp file and ATOMIC_MOVE without fsync of the file or directory. Leftover .tmp files are never cleaned. **Fix:** Fsync file and directory before and after rename, and remove stale .tmp files at start.
- [ ] 🟡 **On-disk and wire formats are documented and versioned.** The envelope JSON file format and filename scheme are undocumented and unversioned (TODO.md). **Fix:** Document the format with a version field and a migration note.
- [ ] 🟡 **Performance claims have a benchmark.** README claims the ~10 msg/s ceiling is removed, and the goal cites a benchmark. No benchmark is in the evidence. **Fix:** Add a repeatable JMH benchmark with recorded results.
- [ ] 🟡 **Compatibility is checked automatically for a library with dependents.** The pom and CI have no API compatibility check, despite downstream dependents. **Fix:** Add japicmp against the previous release in CI.
- [ ] 🟡 **The trust boundary is stated and input is validated at it.** The trust boundary is not stated: in-process caller trusted? store directory trusted? **Fix:** State that callers are trusted and that the store directory is host-protected.
- [ ] 🟡 **Replayed or parsed data is handled safely.** sendUnprocessed calls fromJSON without a guard, so one corrupt file throws and aborts the whole replay. **Fix:** Catch parse errors per file and quarantine corrupt files.
- [ ] 🟡 **Sensitive data is not kept or logged in clear unless that is a decision.** Envelopes are persisted as clear JSON in the user app-data directory with no recorded decision. **Fix:** Record that payloads are stored in clear and that the host owns protection.
- [ ] 🟡 **The build is reproducible and the target is tested.** CI clones ra-common HEAD rather than pinned 1.2.0, and tests on JDK 17 only while the target is 11. **Fix:** Check out the ra-common v1.2.0 tag and add JDK 11 to the CI matrix.
- [ ] 🟡 **Swallowed errors.** appendDelivered and deadLetter IOExceptions are only logged. Callers proceed as if they succeeded. **Fix:** Propagate failures to the listener and avoid acking on failure.
- [ ] 🟡 **Build, buy or reuse is a decision for each major capability.** No recorded reason for building rather than reusing an existing in-process bus library. **Fix:** Record the build-versus-reuse rationale.
- [ ] 🟡 **Shared components have a lifecycle and versioning.** A shared component with no deprecation path. Published via jitpack/local only (TODO.md). **Fix:** Publish to a real repository with a stated deprecation process.
- [ ] 🟡 **Key-person risk is identified with a mitigation.** One maintainer for seven ports. Key-person risk is not recorded. **Fix:** Record the risk with a mitigation such as release docs and a co-maintainer.
- [ ] 🟡 **A risk register has an owner and a status for each risk.** risk-ee1187f5 "The adaptive SEDA controller is not implemented, so a sta..." lacks status; risk-93dd2efa "AtLeastOnce replays envelopes after a crash, so consumers..." lacks status; risk-bd402213 "The deliversPointToPoint test is flaky under repeated bac..." lacks status.
- [ ] 🟡 **Builds and releases are automated.** ci.yml runs tests only. There is no automated release, and publishing is jitpack only. **Fix:** Add a tag-triggered release job.
- [ ] 🟡 **Supported runtime versions are stated and tested.** Java 11 is the stated target, but CI runs only JDK 17. **Fix:** Test on JDK 11 and 17.
- [ ] 🟡 **The resource footprint is documented and configurable.** ra.sedabus.pool.max, the retry timer thread and the default store directory are not documented in the README. **Fix:** Document threads, disk use, defaults and properties in one place.
- [ ] 🟢 **Structural decisions are recorded with their alternatives.** Decisions are recorded without rejected alternatives, for example a polling pool or a broker. **Fix:** Add the alternatives considered to the key decisions.
- [ ] 🟢 **Change is easy where change is expected.** No metrics hook or controller seam exists. Per-stage permits are fixed at register time. **Fix:** Add a ChannelMetrics listener and an adjustable concurrency API as the 2.0 seam.
