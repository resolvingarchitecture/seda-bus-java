## Design quality · 48%

**Progress: 6 of 43 tasks done (14%)** ▰▱▱▱▱▱▱▱▱▱

- [ ] 🔴 **The public surface is explicit and the rest is internal.** SEDAMessageChannel is public with tuning setters. There is no module-info, and the API surface is not listed. **Fix:** List the supported public API and add module-info exporting only ra.sedabus.
- [ ] 🔴 **The public contract is documented.** Javadoc is partial. Nullability, thread-safety and error behaviour per public method are not stated. **Fix:** Document inputs, returns, errors and thread-safety for each public method.
- [ ] 🔴 **A versioning and compatibility policy exists.** No versioning or deprecation policy appears. Large behaviour changes sit under 'Unreleased' while the pom says 1.3.1. **Fix:** State semver rules and what counts as breaking.
- [ ] 🔴 **Lifecycle is defined, including what happens to work in flight.** start() is not idempotent: a second call replaces pool and timer without stopping them. Channel drainWithin ignores in-flight envelopes. **Fix:** Guard start against double calls and count in-flight work in drain.
- [ ] 🔴 **Thread-safety is stated for every shared component.** DESIGN concurrency notes are general. Thread-safety is not stated per public class or method. **Fix:** Annotate each public class with its thread-safety contract.
- [ ] 🔴 **Every queue, buffer, cache and map is bounded, with a stated policy at the limit.** Queues, dedup and in-memory dead letters are bounded, but deadLetter.json grows without limit (TODO admits this). **Fix:** Add rotation or a cap for deadLetter.json.
- [ ] 🔴 **Failure modes are listed for each operation.** Failure modes are described by theme in DESIGN, not per public operation. **Fix:** Add a per-operation failure table.
- [ ] 🔴 **Delivery guarantees match the implementation.** send(): an envelope-level AtLeastOnce/ExactlyOnce on an AtMostOnce channel is not persisted, because persist() returns true when channelDir is null. **Fix:** Reject or persist guaranteed envelopes on non-persistent channels, and document it.
- [ ] 🔴 **Failure paths and concurrency are tested, and time and I/O can be faked.** Failure and concurrency tests exist. There are no crash or partial-write tests, no injectable clock or FS, and tests rely on sleeps. **Fix:** Add fault-injection tests and inject a clock and store.
- [ ] 🔴 **Documentation matches the code.** TODO says retries re-queue immediately (code backs off). DESIGN routing pseudocode omits put-back. The Backpressure Javadoc says DropNewest discards silently and Block has a timeout. **Fix:** Update TODO, DESIGN and the Backpressure Javadoc to match the code.
- [ ] 🔴 **Contracts are machine-readable and tested.** CORRECTNESS_SUITE.md is prose. TODO asks for shared test vectors across ports. **Fix:** Publish machine-readable conformance vectors that every port runs.
- [ ] 🔴 **Change follows compatibility rules.** No compatibility or deprecation rules are stated for the MessageBus surface or the file formats. **Fix:** Define additive-change rules and a deprecation window.
- [ ] 🔴 **Delivery semantics and ordering are stated for each channel.** Delivery levels are stated per channel. Ordering per channel is not stated. **Fix:** State ordering guarantees per channel mode.
- [ ] 🔴 **Complexity does not exceed team capacity.** One maintainer keeps seven ports in lockstep without shared machine-checked vectors. **Fix:** Automate cross-port conformance to cut manual load.
- [ ] 🟡 **Persistence sits behind a boundary.** persist, removePersisted, delivered.log and deadLetter I/O all sit inline in SEDAMessageChannel. **Fix:** Extract a ChannelStore class for envelope, dead-letter and delivered-id files.
- [ ] 🟡 **Components are cohesive and of reasonable size.** SEDAMessageChannel (~600 lines) combines delivery, retry, dead-letter, persistence, dedup and lifecycle. **Fix:** Split out persistence/dedup and the retry scheduler.
- [ ] 🟡 **Failures are reported in one consistent way.** Failures surface as boolean returns, DLC error messages, callback replies and the listener. Type-filter rejection adds no error message. **Fix:** Document one failure model and apply it to every rejection path.
- [ ] 🟡 **Ordering guarantees are stated, and so is where they stop.** Ordering is not stated. Retries re-enter at the queue tail, and concurrency above 1 reorders delivery. **Fix:** Document FIFO scope and what breaks it.
- [ ] 🟡 **Durable writes follow a stated protocol.** persist() uses temp file plus ATOMIC_MOVE, with no fsync of the file or directory. The protocol is undocumented. **Fix:** fsync the file and directory, and document the write protocol.
- [ ] 🟡 **On-disk and wire formats are documented and versioned.** Envelope JSON, filenames and delivered.log carry no version and no documented format (TODO item). **Fix:** Document and version the on-disk formats.
- [ ] 🟡 **Compatibility is checked automatically for a library with dependents.** pom.xml has no japicmp or similar API-compatibility check. **Fix:** Add japicmp against the previous release.
- [ ] 🟡 **The trust boundary is stated and input is validated at it.** The trust boundary (in-process caller, files in the store directory) is not stated anywhere. **Fix:** State that callers are trusted and replayed files are validated.
- [ ] 🟡 **Replayed or parsed data is handled safely.** sendUnprocessed: e.fromJSON on a corrupt file is not caught, so one bad file can abort replay. **Fix:** Catch parse errors and quarantine bad files.
- [ ] 🟡 **The build is reproducible and the target is tested.** CI builds ra-common from HEAD, not 1.2.0, and tests only JDK 17 while the target is 11. **Fix:** Pin ra-common to the 1.2.0 tag and add a JDK 11 CI leg.

- [ ] 🟡 **Build, buy or reuse is a decision for each major capability.** There is no recorded reason for building rather than reusing an existing in-process bus library. **Fix:** Add a build-vs-reuse decision.
- [ ] 🟡 **Shared components have a lifecycle and versioning.** Owner and versions exist. No deprecation path or release process is documented. **Fix:** Document the release and deprecation process.
- [ ] 🟡 **Key-person risk is identified with a mitigation.** A single maintainer owns seven ports. Key-person risk is not recorded. **Fix:** Record the risk with a mitigation.
