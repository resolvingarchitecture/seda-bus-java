## Other Improvements

**More high-severity problems**

- [ ] 🔴 Lifecycle is defined, including what happens to work in flight. Document shutdown semantics per service level, including idempotent close.
- [ ] 🔴 No failure is silent. Report drops through an event hook or counter.
- [ ] 🔴 Retry is bounded, backed off, and safe. Document the retry maximum, backoff and jitter.
- [ ] 🔴 Deduplication state is as durable as the guarantee it supports. State where delivered ids are persisted and when.
- [ ] 🔴 Writes are idempotent or deduplicated. See RULE-APP-052.
- [ ] 🔴 Recovery after a partial write is defined. Ignore and remove temp files at start.
- [ ] 🔴 The project can continue if its owner is unavailable. Write release and access instructions a successor can use.
- [ ] 🔴 Change follows compatibility rules. Adopt additive-only changes and a deprecation window.
- [ ] 🔴 Delivery semantics and ordering are stated for each channel. State ordering for each service level.
- [ ] 🔴 Complexity does not exceed team capacity. State the capacity plan or a prioritised port set.
