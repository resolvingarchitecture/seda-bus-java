## Design quality · 48%

**Progress: 6 of 43 tasks done (14%)** ▰▱▱▱▱▱▱▱▱▱

- [ ] 🔴 **The public contract is documented.** Javadoc is partial. Nullability, thread-safety and error semantics per public method are not stated. **Fix:** Document inputs, returns, errors and thread-safety on each public method.
- [ ] 🔴 **A versioning and compatibility policy exists.** No versioning or deprecation policy appears in README, DESIGN or CHANGELOG. **Fix:** Adopt SemVer and state what counts as breaking.
- [ ] 🔴 **Lifecycle is defined, including what happens to work in flight.** After restart(), channels stay paused (accepting=false) and are never unpaused. Calling start() twice leaks the earlier pool. **Fix:** Make start/restart idempotent and reset channel state.
- [ ] 🔴 **Thread-safety is stated for every shared component.** DESIGN concurrency notes are general. No per-class thread-safety statement exists for SEDAMessageChannel's public methods. **Fix:** State thread-safety per public class.
- [ ] 🔴 **Every queue, buffer, cache and map is bounded, with a stated policy at the limit.** deadLetter.json grows unbounded (TODO admits this). Block uses queue.put with no timeout, despite the enum doc. **Fix:** Rotate dead-letter files and add a Block timeout.
- [ ] 🔴 **Failure modes are listed for each operation.** DESIGN covers retry and shutdown, but not per-operation failure modes such as publish false and persist failure. **Fix:** Add a failure-mode table per public operation.
- [ ] 🔴 **No failure is silent.** giveUp ignores a false return from deadLetter(), then ack deletes the persisted copy, so the record is lost. **Fix:** Keep the persisted copy when the dead-letter write fails.
- [ ] 🔴 **Delivery guarantees match the implementation.** When fanOut partially fails, the whole fan-out is retried, re-publishing copies to subscribers that already accepted them. **Fix:** Track per-subscriber hand-over for fan-out retries.
- [ ] 🔴 **Failure paths and concurrency are tested, and time and I/O can be faked.** Tests rely on sleeps and have no injectable clock or file system. There are no crash-mid-write tests. **Fix:** Inject a clock and store, and add crash-injection tests.
- [ ] 🔴 **Documentation matches the code.** TODO says retry is immediate, but backoff exists. DESIGN says a full queue fails send(), ignoring the four policies. **Fix:** Update TODO and DESIGN to match the code.
- [ ] 🔴 **The project can continue if its owner is unavailable.** Build steps exist, but release process and jitpack/repo access are not documented. **Fix:** Write a release runbook.
- [ ] 🔴 **Contracts are machine-readable and tested.** CORRECTNESS_SUITE.md is prose. Shared test vectors are still a TODO. **Fix:** Publish machine-readable conformance vectors.
- [ ] 🔴 **Change follows compatibility rules.** No compatibility or deprecation rules are recorded for the API or the store format. **Fix:** State additive-change and deprecation rules.
- [ ] 🔴 **Delivery semantics and ordering are stated for each channel.** Delivery semantics are stated per level. Ordering per channel is not stated. **Fix:** Add ordering to the semantics table.
- [ ] 🟡 **Persistence sits behind a boundary.** SEDAMessageChannel does file I/O directly: persist, removePersisted, deadLetter and delivered.log handling. **Fix:** Extract a ChannelStore class that owns all file access.
- [ ] 🟡 **Components are cohesive and of reasonable size.** SEDAMessageChannel (~600 lines) combines queueing, delivery, retry, dead-letter, persistence and dedup. **Fix:** Split out persistence/dedup and retry scheduling.
- [ ] 🟡 **Failures are reported in one consistent way.** Failures surface through several channels: boolean returns, DLC error messages, callbacks, DeadLetterListener and logs. **Fix:** Document which mechanism applies to each failure.
- [ ] 🟡 **Ordering guarantees are stated, and so is where they stop.** Ordering is not stated. Retries re-queue envelopes out of order, and concurrency above one reorders delivery. **Fix:** Document per-channel FIFO limits.
- [ ] 🟡 **Durable writes follow a stated protocol.** persist uses a temp file and ATOMIC_MOVE, but there is no fsync of the file or directory before rename. **Fix:** Fsync file and directory, and document the protocol.
- [ ] 🟡 **On-disk and wire formats are documented and versioned.** The persisted JSON and filename format are unversioned and undocumented (TODO item). **Fix:** Document and version the store format.
- [ ] 🟡 **Compatibility is checked automatically for a library with dependents.** pom.xml has no japicmp or equivalent API-compatibility check. **Fix:** Add japicmp to the build.
- [ ] 🟡 **The trust boundary is stated and input is validated at it.** Trust in the in-process caller and in on-disk files is not stated. **Fix:** State the trust boundary in DESIGN.md.
- [ ] 🟡 **Replayed or parsed data is handled safely.** sendUnprocessed calls fromJSON without a catch, so a corrupt file can abort replay. **Fix:** Catch parse errors and quarantine bad files.
- [ ] 🟡 **The build is reproducible and the target is tested.** pom targets Java 11, but CI runs JDK 17 only and clones ra-common HEAD rather than the pinned 1.2.0. **Fix:** Run CI on JDK 11 and use a tagged ra-common.
- [ ] 🟡 **Swallowed errors.** removePersisted delete failures and drain RuntimeExceptions are only logged. **Fix:** Surface these through counters or the listener.
- [ ] 🟡 **Build, buy or reuse is a decision for each major capability.** No build-vs-reuse rationale is recorded against existing in-process bus libraries. **Fix:** Record why seda-bus is built here.
- [ ] 🟡 **Shared components have a lifecycle and versioning.** ra-common is not on Central, and CI builds it from HEAD. No deprecation path is stated. **Fix:** Release ra-common to a repository with tagged versions.
- [ ] 🟡 **Key-person risk is identified with a mitigation.** A single maintainer owns all seven ports. Key-person risk is not recorded. **Fix:** Record the risk with a mitigation.
- [ ] 🟡 **A risk register has an owner and a status for each risk.** risk-ee1187f5 "The adaptive SEDA controller is not implemented, so a sta..." lacks status; risk-93dd2efa "AtLeastOnce replays envelopes after a crash, so consumers..." lacks status; risk-bd402213 "The deliversPointToPoint test is flaky under repeated bac..." lacks status.
- [ ] 🟡 **Builds and releases are automated.** ci.yml only runs tests. No release or publish automation exists (jitpack/local only). **Fix:** Add a tagged release workflow.
- [ ] 🟡 **Supported runtime versions are stated and tested.** Java 11 is the stated target, but CI tests only on JDK 17. **Fix:** Add a JDK 11 CI matrix entry.
